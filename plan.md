# plan.md — Pediatric Practitioner DB + Parent Chat Agent (Streamlit POC)

## 0) Summary

Build a Streamlit multi-page POC with:

1) **Practitioner Admin page**
   - Search child by name (substring search).
   - If multiple records match, display all results.
   - Create new child record (autogenerated `child_id`).
   - Edit demographics + structured medical history.
   - Append prescriptions (append-only).
   - Maintain vaccine history (entered by staff).

2) **Parent Chat page**
   - Parent enters `child_id` (must exist).
   - AI agent uses stored history silently for context.
   - Provides **high-level guidance** (no medication dosing).
   - Can suggest scheduling a doctor appointment.
   - Detects end-of-chat intent via LLM; on end intent it:
     - highlights **overdue/missing** vaccines and recommends consulting a doctor,
     - highlights **upcoming** vaccines due within next 4 weeks,
     - optionally offers to book appointments.

3) **Appointments are stored in DB**
   - DB-only scheduling (no external calendar integration).
   - Future: add a third Streamlit page to render an appointment calendar view from DB.

POC constraints:
- SQLite DB for now.
- No authentication.
- Chat history kept in session only (not saved to DB).
- Booking available only for existing child records (chat requires valid `child_id`).

## 3) Data model (SQLite)

SQLite file: `data/app.db` (local), or a configurable path.

### Tables

#### `children`
- `child_id` (TEXT, PK) — auto-generated, e.g. `CH-000123`
- `child_name` (TEXT, indexed)
- `dob` (DATE)
- `sex` (TEXT) — `M/F/Other/Unknown`
- `parent_name` (TEXT)
- `parent_phone` (TEXT)
- `parent_email` (TEXT)
- `allergies_text` (TEXT)
- `family_history_text` (TEXT)
- `surgeries_text` (TEXT)
- `medical_free_text` (TEXT)
- `created_at` (DATETIME)
- `updated_at` (DATETIME)

#### `prescriptions` (append-only)
- `id` (INTEGER, PK AUTOINCREMENT)
- `child_id` (TEXT, FK → children.child_id, indexed)
- `date` (DATE)
- `prescriber` (TEXT)
- `dosage` (TEXT) — free-text (may contain multiple meds; no strict schema in POC)
- `duration` (TEXT)
- `notes_summary` (TEXT)
- `created_at` (DATETIME)

> “Update the index” = append a new row in `prescriptions`.

#### `vaccines_administered`
- `id` (INTEGER, PK AUTOINCREMENT)
- `child_id` (TEXT, FK, indexed)
- `vaccine_name` (TEXT)
- `dose_number` (TEXT) — flexible (e.g., `0`, `1`, `Booster-1`)
- `date_given` (DATE)
- `notes` (TEXT)
- `created_at` (DATETIME)

#### `appointments`
- `id` (INTEGER, PK AUTOINCREMENT)
- `child_id` (TEXT, FK, indexed)
- `appointment_type` (TEXT) — `consult` | `vaccine`
- `start_datetime` (DATETIME, indexed)
- `end_datetime` (DATETIME)
- `subject` (TEXT)
- `case_summary` (TEXT) — **LLM summary only**
- `status` (TEXT) — `booked` (future: `cancelled`)
- `created_at` (DATETIME)

### Constraints / validation rules
- No overlaps at booking time:
  - overlap if `(existing.start < new_end) AND (existing.end > new_start)`
- Validate generated slot times align to the slot cadence.

## 4) Vaccine schedule (India UIP) + due logic

### Source + scope
Implement “full childhood schedule” using India’s **National Immunization Schedule (UIP)** as a reference.  
Reference PDF: https://www.mohfw.gov.in/sites/default/files/National%20Immunization%20Schedule.pdf

### Representation decision (POC)
- Store the schedule as a **Python data structure** in `app/vaccines/uip_schedule.py`.
- Keep it in a format that can later be moved to a DB table if needed.

Schedule item fields (suggested):
- `vaccine_name`
- `dose_label` (e.g., `0`, `1`, `2`, `Booster-1`)
- `due_offset` as a `relativedelta(...)` from DOB (weeks/months/years)
- `notes` (optional) — e.g., “JE endemic districts only”

### Due-date computation
- `due_date = dob + due_offset`
- Determine status per scheduled dose:
  - **given** if matching vaccine dose exists in `vaccines_administered`
  - **overdue/missing** if `due_date < today` and not given
  - **upcoming** if `today <= due_date <= today + 28 days` and not given

Chat behavior on end intent:
- If **any overdue/missing**: highlight + advise consulting doctor; offer scheduling.
- If **any upcoming within 28 days**: highlight + offer vaccine appointment on/after due date.

Matching simplification (POC):
- Match by `(vaccine_name + dose_label)` exact string.
- To reduce typos, practitioner UI should use dropdowns from the schedule.

## 5) Appointment slot generation rules

Doctor availability:
- **Mon–Sat**: 10:00–14:00
- **Mon–Fri**: 16:00–19:00

Slot design:
- appointment duration = **25 min**
- buffer = **5 min**
- slot start cadence = every **30 minutes**

Candidate start times:
- Morning: 10:00, 10:30, …, 13:30 (Mon–Sat)
- Evening: 16:00, 16:30, …, 18:30 (Mon–Fri)

Availability:
- Slot is available if no DB appointment overlaps `[start, start + 25min)`.

Suggestion logic:
- If user requests specific dates → show slots for those dates.
- Else show **next 5 available slots starting next day**.

Vaccine appointment suggestion:
- Suggest **first available slot on/after due date**.

Timezone:
- Use local time by default, but keep `APP_TIMEZONE` configurable for consistency.

## 7) LangGraph agent design

### Model + config
- Provider: OpenAI, key via environment variable `OPENAI_API_KEY`.
- Use LangChain + LangGraph.
- Single LangGraph ReAct loop with tools.

### Tools (exact names)
1) `load_child_record(child_id) -> child_profile_json`
   - demographics + medical history + recent prescriptions + vaccine summary

2) `vaccine_check(child_id, window_days=28) -> {overdue: [...], upcoming: [...]}`
   - uses DOB + schedule + vaccines_administered

3) `check_schedule(child_id, requested_dates: optional[list[date]]) -> available_slots`
   - if requested_dates provided, return slots for those dates
   - else return next 5 available slots starting next day

4) `validate_slot(start_datetime, appointment_type) -> {ok: bool, reason?: str}`
   - ensures in working hours, aligned to cadence, not overlapping

5) `book_appointment(child_id, appointment_type, start_datetime, subject, case_summary) -> confirmation`
   - inserts into `appointments`
   - `case_summary` is LLM summary only

### System prompt requirements
- Never give medication dosing.
- Provide high-level guidance and suggest appointment as appropriate.
- For severe symptoms, recommend consulting a practitioner / urgent care.
- Must infer end-of-chat intent internally:
  - if user says bye/thanks/end or conversation naturally closes → treat as end.
  - on end → call `vaccine_check`, then present reminders + offer booking.

Booking rules in chat:
- Only for existing `child_id` (enforced at entry).
- For consult booking: ask for `subject` and a brief condition description, then create **LLM summary** and book.
- For vaccine booking: propose first available slot on/after due date.
